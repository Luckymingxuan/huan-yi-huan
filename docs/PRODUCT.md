# 缓一缓：产品基线

本文档记录项目当前已确认的目标、愿景、要求与限制。后续设计和开发应以此为共同基线；出现新决策时，先更新本文档，再调整实现。

## 产品愿景

“缓一缓”希望在人情绪升高、可能说出或做出冲动行为之前，提供一个及时而克制的打断。

产品不评判情绪，也不试图代替心理咨询。它只帮助用户意识到“此刻的情绪正在升高”，留出一个短暂的缓冲空间。

## 当前唯一目标

现阶段只构建一个核心页面，不增加登录、设置、报告、社区等其他页面。

这个页面完成一条连续体验：

1. 进入页面并开始检测声音强度。
2. 用“情绪值”实时反馈当前声音强度。
3. 当情绪值升高时，通过颜色变化提醒用户。
4. 上滑查看刚才到现在的变化，并选择任意时间点回看。
5. 查看历史时检测仍持续进行。

## 核心概念

### 情绪值

- 当前版本使用麦克风输入振幅推算一个 `0–100` 的相对值。
- 这个值暂称“情绪值”，用于原型验证。
- 它不是经过校准的物理分贝值，也不是医学或心理学意义上的情绪诊断。
- 同一个人、同一台设备上的相对变化比跨设备绝对值更有意义。

### 三档状态

暂定阈值，后续根据真实使用数据调整：

| 情绪值 | 状态 | 颜色 | 意图 |
| --- | --- | --- | --- |
| `0–44` | 平稳 | 蓝色 | 保持觉察，不制造焦虑 |
| `45–71` | 升高 | 橙色 | 温和提醒用户留意 |
| `72–100` | 强烈 | 红色 | 明确提示先停一下 |

## 单页结构

### 收起状态

- 页面中央显示较大的情绪值和彩色圆环。
- 圆环颜色随三档状态变化。
- 底部是可上滑图层。
- 图层收起时显示最近一小段情绪直方图，以及右侧的持续检测时间。

### 展开状态

- 底部图层上滑成为主要内容区。
- 中央圆环丝滑收拢，只保留顶部的情绪值；数值检测不中断。
- 主区域显示持续增长的情绪直方图。
- 黑色圆点标识当前选中的数据点。
- 用户可左右滑动或点击图表，查看对应时间和情绪值。
- 图层可以再次下滑回到收起状态。

## 交互要求

- 页面必须支持触摸上滑、下滑，也支持点击手柄和键盘操作。
- 圆环到纯数值的变化应是连续的形态和位置动画，避免突然切换。
- 数据记录、计时和颜色更新不能因为图层展开而停止。
- 浏览器要求用户授权麦克风，因此首次检测必须包含明确的启动动作和权限说明。
- 麦克风权限被拒绝或设备不可用时，应给出可理解的恢复提示。

## 视觉方向

- 极简、安静、克制，借鉴 Apple 产品的内容优先、充足留白和细腻动效。
- 必须沿用项目已初始化的 shadcn/ui **Luma** 预设与 Base UI 底层。
- 避免仪表盘堆砌、强装饰、渐变滥用和游戏化表达。
- 颜色主要承担情绪状态含义，其余界面保持中性。
- PC 与手机保持同一信息结构和交互逻辑，不设计两套产品；以手机端尺寸和触控为第一优先级。

## 技术与隐私限制

- 当前使用浏览器 Web Audio API，只在本地实时分析声音。
- 当前实现不上传、不保存、不回放录音内容。
- 刷新页面后历史数据可以清空；持久化不在当前范围内。
- 浏览器不能可靠地把麦克风振幅换算成真实声压级，因此当前值只能作为相对反馈。
- 麦克风通常只允许在 `localhost` 或 HTTPS 环境使用。
- 页面在后台、设备锁屏或系统限制麦克风时，检测可能暂停。

## 当前不做

- 不做真正的情绪识别或语义分析。
- 不做诊断、治疗建议或危机干预承诺。
- 不做账号系统、云同步、长期报告和多人功能。
- 不保存原始音频。
- 不扩展第二个业务页面。

## 当前验收标准

- 手机和 PC 均可进入同一个核心页面。
- 用户授权后能看到实时变化的情绪值。
- 蓝、橙、红三档颜色按阈值切换。
- 收起状态显示圆环、近期小直方图和检测时长。
- 图层可顺滑上滑展开、下滑收起。
- 展开时圆环消失但情绪值保留，检测继续。
- 展开图表支持选择历史点，并显示该点的时间与情绪值。
- 页面基于 Luma 预设，lint 和生产构建通过。
